If your audio plugins are sputtering, glitching, or dropping out randomly during development, there's a high chance your logging is the culprit. You threw a quick print statement into your audio callback to debug a buffer issue, and now the whole engine is choking.

Why standard logging destroys audio performance
The golden rule of audio programming is that you can never block the audio thread. You have a few milliseconds to fill the audio buffer, and if you miss that deadline, the user hears a dropout.

Functions like std::cout, printf, and std::ofstream are fundamentally unsafe for the audio thread for two reasons:
1. They take locks: The C/C++ standard library protects its streams with mutexes. If another thread is currently printing, your audio thread will block and wait for it to finish.
2. They do I/O: Writing to a console or disk is incredibly slow and unpredictable compared to the tight deadlines of an audio callback.

    // FATAL: std::cout blocks, locks, and allocates memory!
    std::cout << "Processing buffer size: " << buffer.getNumSamples() << std::endl;
    
    // ... DSP code ...
}

Even juce::Logger::writeToLog() is generally unsafe in the audio thread because it eventually formats strings and writes to disk or stderr.

The RIGHT way: Lock-free queues
To log safely from the audio thread, you need to defer the formatting and I/O to a background thread. You do this by pushing raw data into a lock-free queue (like juce::AbstractFifo or moodycamel::ConcurrentQueue).

Wait, why raw data?
You cannot pass a std::string into your queue. Constructing or concatenating std::string allocates memory on the heap. Memory allocation uses locks under the hood, meaning new and malloc are strictly forbidden in the audio thread.

Instead, define a plain old data (POD) struct using basic types and fixed-size character arrays.

A production-ready RealtimeLogger
Here is a simplified JUCE implementation using juce::AbstractFifo to pass structs to a background thread.

First, define the structure of your log message:

struct LogEvent
{
    enum class Type { BufferSize, GainChange, Error };
    Type type;
    float floatValue;
    int intValue;
    char text[32]; // Fixed-size array, no allocation!
};

Next, create the logger class that inherits from juce::Thread:

class RealtimeLogger : public juce::Thread
{
public:
    RealtimeLogger() : juce::Thread("AudioLoggerThread")
    {
        startThread();
    }

    ~RealtimeLogger() override
    {
        stopThread(1000);
    }

    // Called from the audio thread
    void logBufferSize(int size)
    {
        auto writeHandle = fifo.write(1);
        if (writeHandle.blockSize1 > 0)
        {
            auto& event = buffer[writeHandle.startIndex1];
            event.type = LogEvent::Type::BufferSize;
            event.intValue = size;
        }
    }

    // Called from the audio thread
    void logError(const char* message)
    {
        auto writeHandle = fifo.write(1);
        if (writeHandle.blockSize1 > 0)
        {
            auto& event = buffer[writeHandle.startIndex1];
            event.type = LogEvent::Type::Error;
            juce::String(message).copyToUTF8(event.text, sizeof(event.text) - 1);
        }
    }

    // Called on the background thread
    void run() override
    {
        while (!threadShouldExit())
        {
            auto readHandle = fifo.read(fifo.getNumReady());
            
            for (int i = 0; i < readHandle.blockSize1; ++i)
                processEvent(buffer[readHandle.startIndex1 + i]);
                
            for (int i = 0; i < readHandle.blockSize2; ++i)
                processEvent(buffer[readHandle.startIndex2 + i]);
                
            // Sleep to prevent maxing out the CPU
            wait(50);
        }
    }

private:
    void processEvent(const LogEvent& event)
    {
        // Now we are safely off the audio thread. 
        // We can allocate strings and do I/O.
        switch (event.type)
        {
            case LogEvent::Type::BufferSize:
                std::cout << "[AUDIO] Buffer size changed to: " << event.intValue << std::endl;
                break;
            case LogEvent::Type::Error:
                std::cout << "[ERROR] " << event.text << std::endl;
                break;
            default: break;
        }
    }

    static constexpr int queueSize = 1024;
    juce::AbstractFifo fifo { queueSize };
    std::array<LogEvent, queueSize> buffer;
};
[/CODE BLOCK]

Summary
- Never block: std::cout, printf, and disk I/O are forbidden in the audio callback.
- Never allocate: std::string uses the heap and can take locks. Use fixed-size char arrays and primitive types.
- Defer the work: Pass lightweight structs through a lock-free queue to a lower-priority background thread, and do your string formatting and printing there.
