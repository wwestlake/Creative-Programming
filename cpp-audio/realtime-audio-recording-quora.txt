The problem: Disk I/O in the audio callback
You're trying to record incoming audio to a WAV file, but your UI freezes and you're getting terrible audio glitches (dropouts). The golden rule of audio programming is that you never block the audio thread. Disk I/O is notoriously unpredictable and incredibly slow compared to the strict deadlines of a real-time audio callback.

The WRONG Way: Writing to disk in processBlock
It's tempting to just write incoming samples straight to disk the moment they arrive.

[CODE BLOCK]
void AudioRecorder::processBlock(juce::AudioBuffer<float>& buffer, juce::MidiBuffer& midiMessages)
{
    // WRONG: Never do this in the audio thread!
    if (isRecording && writer != nullptr)
    {
        // This will block, causing glitches and dropouts.
        writer->writeFromAudioSampleBuffer(buffer, 0, buffer.getNumSamples());
    }
}
[CODE BLOCK]

This works fine for a few milliseconds until the operating system decides it needs to spin up a drive, page some memory, or deal with a background process. Your audio callback misses its deadline, the sound card runs out of samples, and you get a loud click.

The RIGHT Way: The Lock-Free Ring Buffer
The solution is decoupling the audio thread from the disk I/O thread. We do this using a lock-free ring buffer (FIFO).

Here is how it works:
1. The audio callback acts purely as a producer. It pushes incoming samples into the FIFO and returns immediately.
2. A background thread acts as a consumer. It continuously polls or waits on the FIFO. When enough samples are available, it pulls them out and writes them to the file system.

Because the FIFO is lock-free, the audio thread never waits for a mutex and is never blocked by the disk thread.

Handling Disk Stalls
To handle inevitable disk stalls, your FIFO needs to be large enough to hold samples while the background thread is blocked. A good rule of thumb is a 2 to 5-second buffer. At 44.1kHz, a 2-second stereo buffer is roughly 176,400 samples—which is a trivial amount of RAM (under 1 MB), but buys you massive safety margins against disk hiccups.

Production Implementation (JUCE)
While you can build your own lock-free FIFO and background thread, JUCE provides a robust wrapper specifically for this problem: AudioFormatWriter::ThreadedWriter.

Here's how you set it up properly:

[CODE BLOCK]
class AudioRecorder
{
public:
    AudioRecorder() : backgroundThread("Audio Recorder Thread")
    {
        backgroundThread.startThread();
    }

    ~AudioRecorder()
    {
        stopRecording();
        backgroundThread.stopThread(1000);
    }

    void startRecording(const juce::File& file)
    {
        auto* format = new juce::WavAudioFormat();
        std::unique_ptr<juce::AudioFormatWriter> writer(
            format->createWriterFor(new juce::FileOutputStream(file),
                                    44100.0, 2, 16, {}, 0));
        
        if (writer != nullptr)
        {
            // Create a threaded writer with a large lock-free FIFO (e.g., 2 seconds)
            // 44100 samples/sec * 2 seconds = 88200 samples
            threadedWriter.reset(new juce::AudioFormatWriter::ThreadedWriter(
                                     writer.release(), 
                                     backgroundThread, 
                                     88200));
        }
    }

    void stopRecording()
    {
        threadedWriter.reset();
    }

    void processBlock(const juce::AudioBuffer<float>& buffer)
    {
        if (threadedWriter != nullptr)
        {
            // Lock-free push into the FIFO. Safe for the audio thread!
            threadedWriter->write(buffer.getArrayOfReadPointers(), buffer.getNumSamples());
        }
    }

private:
    juce::TimeSliceThread backgroundThread;
    std::unique_ptr<juce::AudioFormatWriter::ThreadedWriter> threadedWriter;
};
[CODE BLOCK]

Summary
* Never perform disk I/O inside the real-time audio callback.
* Use a lock-free ring buffer to decouple sample collection from disk writing.
* Size your FIFO generously (2-5 seconds) to ride out OS disk stalls.
* In JUCE, use TimeSliceThread and AudioFormatWriter::ThreadedWriter to handle the heavy lifting safely.
